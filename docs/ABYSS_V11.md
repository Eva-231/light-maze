## セーブ互換

匿名保存・バックアップ・競合検出・再送を維持。format8へ追加的な任意フィールドを導入。
`abyss.revivalStock`、探索の`revivals`/`revivalCharges`、装備`abyssGrade`/`enchants`、図鑑の追加カテゴリを検証する。
旧データでは未設定の復活在庫/回数は0、深淵GradeはIとして扱う。旧装備のロール値や所持数は削らない。
既存装備ID 0〜95は不変、新能力装備を96〜103へ追加。既存MYTHICは92〜95。
中断セーブにも残り蘇生回数を保存。途中で持ち帰り品を増殖させない。

## 検証

`npm test` / `npm run verify` はローカルで成功。
従来テストに加え、全99階、ボス/安全階、光補給増、深度5%抽選、Grade、4枠上限、重複倍率、消費・保護、交換、3回制限、旧ID、セーブ往復を検証。
実際のgame.jsで死亡→停止確認→保存→蘇生→操作再開も検証。
`browser-smoke.mjs` は390×844のWebGL、同時タッチ、階層/中断/再開、鑑定、アバター、図鑑、MP3に加え、新工房、7ページ説明、蘇生、25/99Fの安全性を確認する。
最終のブラウザCI結果とコミットはPR #2を参照。

## パフォーマンス・残る測定

ゲームの一時FX最大48、敵最大20、連鎖対象最大8を維持。
追加の雷鎖は3体、追撃は1体。鑑定3Dは260×220、DPR1、最大約15fps、部品数を制限し終了時にGPU資源を破棄する。
既存音声13ファイル、画像、vendorは変更なし。独立版の `npm start` / `npm run build` / Dockerで運用可能。

未実測: iPhone/iPad実機のFPS・発熱・Safari固有操作と、標準ビルドの実際のクリア率。指定の50%/20%/40%は設計目標であり、達成を保証する測定結果ではない。
オンラインランキングは従来の整合性検証を維持するが、クライアント改変を完全には防止しない。
