## 能力の扱い

候補の名称は `abyss-gear.js` に定義。攻撃・被弾・撃破・罠・採掘・魔法・LIGHTの実処理に接続する。壁反射は1回、範囲/連鎖の追加対象は最大8体。追加攻撃から同じ撃破連鎖を再帰発火させない。時間停止は敵の行動を止め、プレイヤーは動ける。装備進化と図鑑発見は死亡しても残る。

3スロット制は維持。固有能力は再抽選で消えず、任意の最強能力を自由に指定することはできない。お気に入り/装備中の分解・売却を拒否する。

## セーブ互換

- format 8。旧format 1〜7の通貨・装備・ID・お気に入り・章の星・履歴・旧trialLevelを保持。
- `abyss`, `codex`, `shards` に安全な初期値を補完。
- 未帰還の戦利品は銀行に含めず、中断データにのみ保持。通常の画面再読み込みで未中断の探索を再開・巻き戻しはしない。
- 中断データ消費と帰還確定は別の保存操作。重複run IDによる二重確定を拒否。
- 匿名保存・revision競合検出・未送信outbox・バックアップを継続。
- Worker/独立Nodeサーバー両方で新装備とチェックポイントを検証。通常はメールアドレス不要。
- 静的ホスティングでは既存どおり端末保存。オンラインランキングには独立Nodeサーバーまたは既存Worker/DBが必要。

## 検証

ローカルで `npm test` と `npm run verify` 成功。

`abyss-tests.mjs` の14スイートと既存の回帰検証を実施。実際のgame.jsを使うライフサイクルテストで、階層移動→中断→保存→再開→帰還/死亡を検証。99階の到達可能性、20体上限、自然湧き条件、6万回の通常排出率、装備/シナジー/進化/工房/旧セーブも検証。Three.jsの実ジオメトリ生成と破棄はGPUなしで検証。

`npm run verify` はソースサーバーとビルド済み配布物の両方を起動し、ホーム/音声/新モジュール/匿名v8セーブ/APIを確認。

追加の `npm run test:browser` はPlaywrightの実WebGL描画・スマホ2本指操作・中断後のページ再読み込み・MYTHIC一括鑑定・アバター・図鑑・MP3デコードを検証し、スクリーンショットを保存する。実ブラウザ検証はGitHub Actionsで実行する。PRのChecksで結果、`browser-smoke` アーティファクトでスクリーンショットを確認できる。ブラウザのネイティブタイマー、MYTHICの「溜め→確定→開封」、回復半減と呪いの併用、イベント説明、進化後の図鑑も回帰検証する。ローカル環境のブラウザバイナリ取得はタイムアウトしたため、実描画の結果はCIを正とする。

## レビュー上の留意点

- 本編クリア率50%/20%、LEGEND装備時40%は調整目標。プレイテスターの実測値ではない。操作スキル・ビルド差の実機プレイが必要。
- iPhone/iPad実機のフレームレート、音量、視認性は未測定。
- 一時FXは48個、連鎖対象は8体まで。死んだ敵と回収済みドロップの描画リソースを定期回収し、階層切替でも破棄。元のパーティクル/ビームプールを保持。
- ランキングはサーバーで数式・入力値を検証するが、ブラウザ発のプレイ記録に対する完全な不正防止ではない。
- このPRはmainへマージせず、公開中のSite/Pagesを変更しない。

## 開発

Node.js 22.13以上（CIは24）。依存追加なしで `npm start` → `http://localhost:4173`。

```sh
npm test
npm run verify
# 任意の実ブラウザ検証
npm install --no-save --package-lock=false playwright@1.62.1
npx playwright install chromium
npm run test:browser
```

バランスは `abyss-rules.js`、装備追加は `abyss-gear.js`、能力の処理は `gear-effects.js`、セーブ境界は `abyss-run.js`/`save-schema.js` を主に編集する。
